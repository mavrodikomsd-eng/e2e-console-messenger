> **Сервер — «слепой» ретранслятор.** Он видит только маршрутные имена и ни одного
> сообщения: каждый текст шифруется отдельным ключом для каждого получателя,
> а отпечатки ключей пиров защищают от подмены (TOFU).

## 🔍 Как это работает

```
 ┌──────────┐         ┌─────────────────────┐         ┌──────────┐
 │  Алиса   │         │   Сервер (слепой)    │         │    Боб   │
 │          │         │                     │         │          │
 │ ECDH(скА,│  M-кадр │   видит только:     │  M-кадр │ ECDH(скБ,│
 │ pubБ)=ключ──────▶   │  • маршрутные имена │   ──────┼─▶ pubА)=ключ
 │ AES-GCM  │         │  • комнаты           │         │ AES-GCM  │
 │ AAD=pubА │         │  • размер кадров     │         │ AAD=pubБ │
 └──────────┘         └─────────────────────┘         └──────────┘

   текст сообщения ◀── НЕ ВИДЕН НИ СЕРВЕРУ, НИ ПОДСЛУШАТЕЛЮ ──▶ текст сообщения
```

**Три уровня защиты на каждом сообщении:**

| Уровень | Механизм | От чего защищает |
|---|---|---|
| 🔑 Конфиденциальность | `ECDH(мой_ск, публичный_получателя)` → AES-256-GCM | чтение сервером и перехватчиком |
| 🏷️ Целостность | GCM-тег + **AAD = публичный ключ отправителя** | подделку «от чужого имени» |
| 👤 Аутентификация пира | TOFU-отпечатки (`tofu.json`), алерт при смене ключа | MITM на обмене ключами |

<details>
<summary><b>📖 Подробнее о криптографии — нажми, чтобы раскрыть</b></summary>

1. При первом запуске клиент генерирует пару **X25519** (`identity.key`) и регистрирует
   публичный ключ на сервере.
2. Для отправки сообщения берётся публичный ключ получателя → общий секрет через ECDH
   → сеансовый ключ AES-256.
3. Сообщение шифруется **AES-256-GCM**: `base64(nonce ‖ ciphertext ‖ tag)`.
4. В роли AAD выступает публичный ключ отправителя — расшифровать сообщение,
   выдав себя за другого, математически невозможно.
5. Пароли аккаунтов хранятся как **Argon2id** (`accounts.json`, права 0600).

⚠️ **Ограничение:** используется статический ECDH — компрометация `identity.key`
раскрывает прошлую переписку (нет forward secrecy). Осознанный компромисс v1.5.
</details>

## ✨ Возможности

### 🔐 Криптография и аккаунты
- 🔑 **Своя идентичность у каждого** — пара X25519 в `identity.key`, публичный ключ регистрируется на сервере.
- 🔒 **E2E AES-256-GCM** — per-recipient шифрование, встроенный контроль целостности.
- 🛡️ **Защита от подмены имени** — AAD привязывает шифротекст к ключу отправителя.
- 🕵️ **TOFU во всех клиентах** — отпечатки пиров, предупреждение при смене ключа, `/trust` / `/fingerprints`.
- 🔐 **Аккаунты с паролями** — `/register` и `/login`, пароли как **argon2id**, лимит попыток входа.

### 💬 Общение
- 💬 Комнаты: `/createroom <имя> [пароль]`, `/join`, `/leave` — приватные комнаты с паролем.
- 📂 Передача файлов `/file <путь>` — шифруется на каждого получателя.
- 🤫 Личные сообщения `/msg Имя текст` — доставляются только адресату.

### 🖥️ Реализации
| Компонент | Язык | Назначение |
|---|---|---|
| `server.go` | 🐹 Go | **основной сервер** — производительный ретранслятор |
| `server.py` | 🐍 Python | референсный сервер (удобен для разработки/тестов) |
| `client.py` | 🐍 Python | консольный клиент + модули (`modules/`) |
| `go_client/` | 🐹 Go | CLI-клиент на stdlib |
| `rust_client/` | 🦀 Rust | клиент без паник на битых данных |
| `libmesh/` | 🔩 C | крипто-ядро (X25519, AES-GCM, argon2) для Python через FFI |
| `web/server_web.py` | 🌐 Python | дашборд мониторинга: онлайн, пользователи, комнаты |

> Дашборд видит **только метаданные** — содержимое сообщений недоступно по дизайну (E2E).

## 🚀 Быстрый старт

### 1️⃣ Запуск сервера
```bash
go build server.go && ./server.exe      # или: python server.py
```
```
[СЕРВЕР] Запущен на 127.0.0.1:1301
[СЕРВЕР] Режим: E2E шифрование (сервер НЕ видит содержимое сообщений)
```

### 2️⃣ Подключение клиентов
```bash
python client.py                        # или go_client/, или rust_client/
```

### 3️⃣ Регистрация и общение
```
>>> /register alice пароль пароль
✅ Авторизация успешна. Можно общаться!
>>> /msg bob привет! Это увидим только мы двое
[Я] -> bob: привет! ...
```

<summary><b>⚙️ Конфигурация</b></summary>

`config.json`:

{
  "server": { "host": "127.0.0.1", "port": 1301,
              "rate_limit": { "max_messages": 30, "window_seconds": 5 },
              "idle_timeout": 600 },

| Переменная | Назначение |

| `MESH_SHARED_KEY` | путь к `secret.key` |
| `MESH_IDENTITY_FILE` | путь к `identity.key` |
| `MESH_WEB_USER` / `MESH_WEB_PASS` | аккаунт веб-дашборда |

## 🔐 Безопасность

- 🗂️ Секреты (`secret.key`, `identity.key`, `accounts.json`, `tofu.json`) — права **0600**, вне git.
- 🧮 Пароли — **argon2id**; сравнение хэшей константное по времени; 5 неудачных входов → отключение.
- 📏 Лимит кадра 1 МБ — битый заголовок не вызовет OOM.
- 🚦 Анти-флуд: 30 кадров / 5 с → отключение; таймауты чтения против «вечных» соединений.
- 📁 Принятые файлы — только в `downloads/`, path-traversal исключён.
- 🚫 Валидация имён: без `; : \x00 \n \r`, длина ≤ 32.

> ⚠️ **Честные ограничения:** нет TLS (канал служебных команд защищён общим `secret.key`),
> публичные ключи не заверяются CA — MITM отсекается только через TOFU-сверку отпечатков,
> нет forward secrecy. Для максимума защиты используйте доверенную сеть и сверяйте
> `/fingerprints` по другому каналу.
