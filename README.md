## ✨ Особенности

### 🔐 Криптография
- 🔑 **Своя идентичность у каждого** — больше никакого общего секрета на всех.
  Каждый клиент генерирует ключевую пару X25519 (`identity.key`) и регистрирует публичный ключ на сервере.
- 🔒 **E2E AES-256-GCM** — контент шифруется ключом, вычисленным через **X25519 ECDH**
  отдельно для каждого получателя (`nonce + ct + tag`, встроенный контроль целостности).
- 🛡️ **Защита от подмены имени** — AAD привязывает шифротекст к публичному ключу отправителя:
  сообщение «от чужого имени» не пройдёт проверку.
- 🔐 **Аккаунты с паролями** — `/register` и `/login`; вход обязателен, пароли хранятся
  в `accounts.json` как **argon2id** (раньше — salted SHA-256, с автопереходом).

### 🧩 Клиенты и серверы
- 🐍 **Python-клиент** — удобный консольный интерфейс.
- 🐹 **Go-клиент** — CLI на Go: весь проект можно держать в одном языке.
- 🦀 **Rust-клиент** — полноценный CLI, тот же протокол и криптография, без паник на битых данных.
- 🔩 **C-ядро libmesh** — общая криптография (X25519, AES-256-GCM, argon2id, фрейминг) на C
  со статик-линковкой libsodium; Python использует его через `libmesh_ffi.py` (фоллбэк — pycryptodome).
- ✳️ **Zig-клиент** (`zig_client/`) — крипто-фундамент (X25519, AES-GCM, SHA-256) собран и проверен
  на Zig 0.16 (`_probe.zig`); сетевая часть — в работе.
- 🚀 **Два сервера** — высокопроизводительный **Go** (рекомендуется) и **Python**.

### 💬 Функции обмена
- 📂 **Передача файлов** — `/file <путь>`, шифруется на каждого получателя.
- 🏠 **Комнаты** — `/join`, `/leave`, `/roommembers`, приватные комнаты с паролем.
- 💌 **Личные сообщения** — `/msg Имя текст` (X25519 E2E).
- ⌨️ **Богатый набор команд** — `/users`, `/rooms`, `/ping`, `/time`, `/status`, `/about`.
- 🌐 **UTF-8** — полная поддержка русского языка и эмодзи.

## 🔐 Что такое E2E и как это работает

1. **Регистрация.** Клиент генерирует пару X25519. Приватный ключ хранится в `identity.key`
   (файл в `.gitignore`, в git он не попадает).
2. **Публичный ключ раздаётся.** Клиент регистрирует публичный ключ на сервере; сервер раздаёт его
   остальным участникам комнаты.
3. **Шифрование на получателя.** Чтобы написать Бобу, Алиса считает общий секрет
   `ECDH(приватный_Алисы, публичный_Боба)` и шифрует им сообщение (AES-256-GCM).
4. **Доставка.** Сервер просто пересылает зашифрованный пакет Бобу. Сам сервер расшифровать его не может —
   у него нет ни приватного ключа Алисы, ни приватного ключа Боба.
5. **Проверка подлинности.** В AAD (дополнительные аутентифицированные данные) подписывается
   публичный ключ отправителя — подменить имя невозможно.

> ### 🎯 Главное
> **Сервер слепой.** Он видит маршрутные имена (`Алиса → Боб`) и служебные команды, но **не видит тексты**.
> Модель trust — **«не доверяй серверу»**: даже взломанный сервер не раскроет содержимое переписки.

│   └── build.bat
├── ✳️ zig_client/          # Порт клиента на Zig

├── 📁 modules/             # Внутренние модули
│   ├── crypto.py           # X25519 + AES-256-GCM
│   ├── libmesh_ffi.py      # ctypes-обвязка над libmesh.dll

| **`modules/crypto.py`** | Криптографический модуль (libmesh через FFI, с фоллбэком на pycryptodome) |
| **`modules/protocol.py`** | Фрейминг и сериализация кадров поверх TCP |

## ⚙️ Установка и зависимости

### 0. Скачай нужные языки

| Инструмент | Где взять | Зачем |
| :--- | :--- | :--- |
| 🐍 **Python 3.8+** | [python.org/downloads](https://www.python.org/downloads/) | Python-клиент / Python-сервер |
| 🚀 **Go 1.18+** | [go.dev/dl](https://go.dev/dl/) | Основной Go-сервер |
| 🦀 **Rust (rustup)** | [rustup.rs](https://rustup.rs/) | Rust-клиент |
| ✳️ **Zig 0.16** | [ziglang.org/download](https://ziglang.org/download/) | Zig-клиент (опционально) |

### 1. Python-клиент/сервер

```bash
git clone https://github.com/mavrodikomsd-eng/e2e-console-messenger
cd per12re
pip install -r requirements.txt
```

### 2. Rust-клиент

```bash
cd rust_client
cargo build --release    # бинарник появится в target/release/
```

### 3. Go-клиент

```bash
cd go_client
go build -o mesh_go_client.exe .
```

> **Замечание о `secret.key`.** У клиентов и сервера должен быть **один и тот же** файл `secret.key`
> (служебный канал команд). Он создаётся автоматически при первом запуске. Go- и Rust-клиенты ищут ключ
> **и в своей папке, и в корне проекта (`../secret.key`)** — держите все процессы в одном каталоге,
> чтобы не появились «свои» ключи, не совпадающие с серверным.

## 🚀 Руководство по запуску

### 1. Запусти сервер (на выбор)

* **Go-сервер (рекомендуется):**
  ```bash
  go run server.go
  ```

* **Python-сервер:**
  ```bash
  python server.py
  ```

### 2. Запусти клиент

* **Python:**
  ```bash
  python client.py
  ```

* **Rust:**
  ```bash
  cd rust_client
  cargo run --release
  ```

* **Go:**
  ```bash
  cd go_client
  go build -o mesh_go_client.exe .
  ./mesh_go_client.exe
  ```

### 3. Как подключаться к серверу на хосте

Все клиенты берут адрес из `config.json`:

```json
{
  "server": { "host": "IP_СЕРВЕРА", "port": 1301 }
}
```

- **На сервере**, чтобы принимать внешние подключения, поставь `"host": "0.0.0.0"`
  (Go-сервер читает `configs.json`, Python — `config.json`).
- **На клиентах** пропиши IP сервера в `config.json`. Go- и Rust-клиенты ищут `config.json`
  в рабочей папке или на уровень выше (`../config.json`).
- Любой параметр можно переопределить переменными окружения: `MESH_HOST`, `MESH_PORT`.

## 🔐 Безопасность

- **Идентичность = ключевая пара X25519.** Каждый клиент держит свою пару в `identity.key`
  (файл **в `.gitignore`**, никогда не попадает в git). Публичный ключ регистрируется на сервере
  и раздаётся участникам — сервер видит только публичные ключи, не секреты.
- **Контент закрыт от сервера.** Сообщения и файлы шифруются AES-256-GCM ключом,
  вычисленным через `ECDH(ваш_приватный, публичный_получателя)`. Сервер видит только
  маршрутные имена, а не текст.
- **Подмена имени невозможна.** AAD (Additional Authenticated Data) = публичный ключ
  отправителя. Попытка написать «от чужого имени» приведёт к отказу расшифровки у получателя
  — сообщение будет отброшено.
- **`secret.key`** остался только для *служебного* канала команд (роутинг, списки). Контент
  пользовательских сообщений от него не зависит.
- **Авторизация обязательна.** До входа сообщения и файлы не принимаются; клиент и сервер
  дают понятное предупреждение вместо «тихого игнорирования».
- **Не делитесь `identity.key`** ни с кем: это ваш приватный ключ.
  Поделиться можно только публичным (он и так раздаётся сервером).

> **Важно:** пока нет TLS, возможен MITM (публичные ключи не заверяются удостоверяющим центром).
> Для максимальной защиты запускайте сервер и клиенты в доверенной сети.

## 🛡️ Хардненинг (правки безопасности)

- 📁 **Принимаемые файлы — только в `downloads/`**: имя сводится к безопасному базовому
  (без каталогов и `..`), запись с правами 0600 — path-traversal исключён.
- 🚫 **Лимит длины кадра** в Rust-клиенте (`MAX_FRAME`): битый заголовок не вызовет OOM.
- 🛡️ **Rust-клиент без паник**: кривые данные из сети/файлов возвращают ошибку, а не роняют процесс.
- 🔒 **Секреты с правами 0600**: `secret.key`, `identity.key`, `accounts.json`.
- 👤 **Ключи и маршрутизация только для вошедших**: `/pubkey`, `/roommembers`
  и адресная доставка не раскрывают не-аутентифицированных пользователей.
- 🧮 **Ограничение попыток входа**: после 5 неудач соединение закрывается, ответы единые,
  сравнение хэшей — константное по времени (`crypto/subtle`, `hmac.compare_digest`).
- ✅ **Валидация имён**: запрещены спецсимволы-разделители ( `;`, `:`, нуль-байт), длина до 32,
  чтобы не отравить каталог ключей.
- 🔐 **Argon2id вместо SHA-256**: для аккаунтов (`argon2-cffi` / `golang.org/x/crypto/argon2`),
  пароли комнат — с солью; старые записи мигрируют при входе.
- 🔢 **Версия протокола**: клиент шлёт номер версии кадром `V` при рукопожатии;
  неподдерживаемые версии отклоняются, старые клиенты работают как раньше.
