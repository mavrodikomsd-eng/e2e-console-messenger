# my-messenger

Консольный чат с E2E шифрованием AES-128. Сервер не видит содержимое сообщений.

## Особенности

- ✅ **E2E шифрование**: AES-128 CBC режим
- ✅ **Многопоточность**: Каждый клиент в отдельном потоке
- ✅ **TCP сокеты**: Надежная передача данных
- ✅ **Команды**: `/users`, `/help`, `/clear`, `/exit`
- ✅ **Логирование**: История чата в `messages.log`
- ✅ **Русский язык**: Полная поддержка UTF-8

## Установка

```bash
# Клонировать репо
git clone https://github.com/yourusername/my-messenger.git
cd my-messenger

# Установить зависимости
pip install -r requirements.txt
```

## Запуск

### Сервер (терминал 1)
```bash
python server.py
# [СЕРВЕР] Запущен на localhost:1301
```

### Клиент (терминал 2, 3, ...)
```bash
python client.py
# Введи своё имя: Alice
```

## Архитектура

### server.py
- Слушает на `localhost:1301`
- Обрабатывает подключение клиентов в отдельных потоках
- Транслирует зашифрованные сообщения всем подключенным клиентам
- Обрабатывает команды `/users`, `/help`, `/clear`, `/exit`
- Логирует сообщения в `messages.log`

### client.py
- Подключается к серверу
- Запускает два потока:
  - **receive_messages**: получает и расшифровывает сообщения
  - **send_messages**: отправляет зашифрованные сообщения
- Поддерживает ввод команд (начинаются с `/`)

### crypto.py
- `encrypt_message(str)` → base64 строка (IV + зашифрованные данные)
- `decrypt_message(str)` → исходное сообщение
- Использует `pycryptodome` (AES-128 CBC)

## Безопасность

⚠️ **Это демонстрационный код!** Для продакшена:
- Используйте HTTPS/TLS вместо сырых TCP сокетов
- Используйте сертификаты X.509
- Используйте более сильную аутентификацию (OAuth2, JWT)
- Используйте PBKDF2 для вывода ключей из паролей
- Логируйте аудит корректно

## Проблемы и их решения

### Ошибка: "startswith first arg must be str or a tuple of str, not bytes"
**Решение**: Данные из сокета приходят как `bytes`, нужно декодировать перед проверкой:
```python
# ❌ Неправильно
if data.startswith("/"):

# ✅ Правильно
data_str = data.decode("utf-8")
if data_str.startswith("/"):
```

### Сервер не запускается на порту 1301
Проверьте:
1. Находится ли процесс на порту: `lsof -i :1301` (macOS/Linux)
2. Убедитесь, что предыдущий сервер остановлен
3. Попробуйте другой порт (измените в `server.py` и `client.py`)
