## ✨ Особенности проекта

- 🔑 **X25519 — своя идентичность у каждого**: больше никакого общего секрета на всех.
  Каждый клиент генерирует свою ключевую пару (`identity.key`) и регистрирует публичный ключ на сервере.
- 🔐 **E2E AES-256-GCM**: контент сообщений шифруется ключом, вычисленным через
  **X25519 ECDH** отдельно для каждого получателя (nonce+ct+tag, контроль целостности).
- 🛡️ **Защита от подмены имени**: AAD привязывает шифротекст к публичному ключу
  отправителя — сообщение «от чужого имени» не пройдёт проверку.
- 📂 **Передача файлов**: `/file <путь>` — файлы так же шифруются на каждого получателя.
- 🏠 **Комнаты**: `/join <комната>`, `/leave`, `/roommembers` — изолированный обмен.
- 🐍 **Python-клиент**: удобный консольный интерфейс.
- 🦀 **Rust-клиент**: полноценный CLI, тот же протокол и криптография.
- 🐹 **Go-клиент**: CLI на Go — весь проект можно держать в одном языке.
- 🚀 **Два сервера**: высокопроизводительный **Go** (рекомендуется) и **Python**.
- ⌨️ **Удобные команды**: `/users`, `/rooms`, `/msg`, `/file`, `/ping`, `/time`, `/status`.
- 🌐 **UTF-8**: полная поддержка русского языка и эмодзи.

## 🏗️ Архитектура и структура файлов

```text
per12re/
├── 🚀 server.go            # Сервер на Go (основной, высокопроизводительный)
├── 🐍 server.py            # Сервер на Python (альтернатива)
├── 🐍 client.py            # Консольный клиент на Python
├── 🦀 rust_client/         # Консольный клиент на Rust
│   ├── Cargo.toml
│   └── src/main.rs
├── 🐹 go_client/           # Консольный клиент на Go
│   ├── go.mod
│   └── main.go
├── config.json             # Конфигурация Python-клиента/сервера
├── configs.json            # Конфигурация Go-сервера
├── requirements.txt        # Python-зависимости
└── 📁 modules/             # Внутренние модули
    ├── crypto.py           # X25519 + AES-256-GCM шифрование
    ├── protocol.py         # Сетевой протокол обмена
    ├── config.py           # Загрузчик настроек
    └── ui.py               # Оформление интерфейса и баннеры
```

| Компонент | Описание |
| :--- | :--- |
| **`server.go`** | Многопоточный сервер на Go: комнаты, маршрутизация, ретрансляция E2E-трафика |
| **`server.py`** | Серверная реализация на Python (тот же протокол) |
| **`client.py`** | Консольный клиент Python: потоки приёма/отправки, комнаты, файлы |
| **`rust_client/`** | CLI-клиент на Rust: тот же протокол, X25519, AES-GCM |
| **`modules/crypto.py`** | Криптографический модуль (pycryptodome) |
| **`modules/protocol.py`** | Фрейминг и сериализация кадров поверх TCP |

## ⚙️ Установка и зависимости

### 0. Скачай нужные языки

| Инструмент | Где взять | Зачем |
| :--- | :--- | :--- |
| 🐍 **Python 3.8+** | [python.org/downloads](https://www.python.org/downloads/) | Python-клиент / Python-сервер |
| 🚀 **Go 1.18+** | [go.dev/dl](https://go.dev/dl/) | Основной Go-сервер |
| 🦀 **Rust (rustup)** | [rustup.rs](https://rustup.rs/) | Rust-клиент |

### 1. Python-клиент/сервер

```bash
git clone https://github.com/mavrodikomsd-eng/e2e-console-messenger
cd per12re
pip install -r requirements.txt
```

### 2. Rust-клиент

```bash
cd rust_client
cargo build --release    # бинарник появится в target/release/
```

> Rust-клиент умеет всё то же, что и Python-клиент: комнаты, файлы, X25519-E2E.
> Go-серверу зависимостей не нужно — только стандартная библиотека.

## 🚀 Руководство по запуску

### 1. Запусти сервер (на выбор)

* **Go-сервер (рекомендуется):**
  ```bash
  go run server.go
  ```

* **Python-сервер:**
  ```bash
  python server.py
  ```

### 2. Запусти клиент

* **Python:**
  ```bash
  python client.py
  ```

* **Rust:**
  ```bash
  cd rust_client
  cargo run --release
  ```

* **Go:**
  ```bash
  cd go_client
  go build -o mesh_go_client.exe .
  ./mesh_go_client.exe
  ```

## 🔐 Безопасность

- **Идентичность = ключевая пара X25519.** Каждый клиент держит свою пару в `identity.key`
  (файл **в `.gitignore`**, никогда не попадает в git). Публичный ключ регистрируется на сервере
  и раздаётся участникам — сервер видит только публичные ключи, не секреты.
- **Контент закрыт от сервера.** Сообщения и файлы шифруются AES-256-GCM ключом,
  вычисленным через `ECDH(ваш_приватный, публичный_получателя)`. Сервер видит только
  маршрутные имена, а не текст.
- **Подмена имени невозможна.** AAD (Additional Authenticated Data) = публичный ключ
  отправителя. Попытка написать «от чужого имени» приведёт к отказу расшифровки у получателя
  — сообщение будет отброшено.
- **`secret.key`** остался только для *служебного* канала команд (роутинг, списки). Контент
  пользовательских сообщений от него не зависит.
- **Не делитесь `identity.key`** ни с кем: это ваш приватный ключ.
  Поделиться можно только публичным (он и так раздаётся сервером).
